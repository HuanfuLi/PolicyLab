    **3. web/src/stores/bootstrapStore.ts** — Zustand store for bootstrap SSE state:

    ```typescript
    interface BootstrapState {
      mode: 'idle' | 'searching' | 'bootstrapping' | 'complete' | 'error';
      selectedLocation: { name: string; country: string; countryCode: string; coordinates: { lat: number; lon: number } } | null;
      agentCount: number;
      scenario: string;
      steps: Array<{ step: string; status: 'pending' | 'active' | 'done' | 'fallback'; fallbackSource?: DataSource }>;
      currentStepIndex: number;
      errorMessage: string | null;
      sessionId: string | null;

      setSelectedLocation: (loc: BootstrapState['selectedLocation']) => void;
      setAgentCount: (n: number) => void;
      setScenario: (s: string) => void;
      startBootstrap: (sessionId: string) => Promise<void>;
      reset: () => void;
    }
    ```

    `startBootstrap` implementation:
    - Set mode to 'bootstrapping'.
    - Initialize steps array: ['geocoding', 'demographics', 'economics', 'governance', 'infrastructure', 'generation'] all 'pending'.
    - Create session first via `POST /api/sessions` (reuse sessionsStore.createSession pattern but with a location-specific idea text like "Mirror: {locationName}").
    - Open SSE via `fetch` to `POST /api/sessions/${sessionId}/bootstrap` with the location data + scenario + agentCount in body.
    - Read the SSE stream using `response.body.getReader()` + TextDecoder (same pattern as existing SSE consumers in the codebase).
    - On `step_start`: update steps[stepIndex].status = 'active'.
    - On `step_done`: update steps[stepIndex].status = 'done'.
    - On `step_fallback`: update steps[stepIndex].status = 'fallback', set fallbackSource.
    - On `complete`: set mode = 'complete', store sessionId.
    - On `error`: set mode = 'error', store errorMessage.
    - Ignore `heartbeat` events.
