    **1. web/src/stores/scenarioStore.ts** — Zustand store for multi-scenario management (per D-15, D-16, D-17):

    ```typescript
    interface ScenarioState {
      tabs: ScenarioTab[];
      activeTabId: string;
      baselineConfig: Partial<EconomyConfig> | null;
      baselineBudget: BudgetAllocation | null;
      runningScenarios: boolean;
      scenarioSessionIds: Record<string, string>; // tab.id -> forked session ID

      initFromSession: (config: Partial<EconomyConfig>, budget: BudgetAllocation) => void;
      addScenario: (name: string) => void;
      removeScenario: (tabId: string) => void;
      renameScenario: (tabId: string, name: string) => void;
      setActiveTab: (tabId: string) => void;
      updateScenarioConfig: (tabId: string, patch: Partial<EconomyConfig>) => void;
      updateScenarioBudget: (tabId: string, budget: BudgetAllocation) => void;
      runAllScenarios: (baseSessionId: string) => Promise<void>;
      reset: () => void;
    }
    ```

    `initFromSession`: Creates a single "Baseline" tab with the session's current config. Sets baselineConfig and baselineBudget.

    `addScenario`: Clones baseline config into a new tab. Generates tab id with `crypto.randomUUID()`. Default name: "Scenario {letter}" (A, B, C...).

    `updateScenarioConfig`: Updates the tab's economyConfig AND computes deltas by comparing each key to baselineConfig. Only keys that differ get a delta entry: `{ from: baselineValue, to: newValue }`.

    `runAllScenarios` (per D-17):
    1. Set `runningScenarios = true`.
    2. For each non-baseline tab:
       a. Call `POST /api/sessions/${baseSessionId}/fork` to create a forked session.
       b. Call `PUT /api/sessions/${forkId}/config` to patch the fork's economyConfig with the tab's overrides.
       c. Store fork ID in `scenarioSessionIds[tab.id]`.
    3. For each fork + baseline: call `POST /api/sessions/${id}/simulate` to start simulation.
    4. NOTE: Per Research open question 3, run sequentially (not truly parallel) to manage LLM costs. Show progress.
    5. After all complete, set `runningScenarios = false`.
    6. The calling component navigates to comparison view.

    interface DiffMarkerProps {
      baselineValue: number | boolean | string;

    - Style: font-size 0.75rem, color `var(--text-muted)`, with the delta colored: positive = `var(--color-yellow, #eab308)`, negative = `var(--color-blue, #3b82f6)`.
    - If values are equal, render nothing.

    - Non-baseline tabs have an X close button.
    - Tab names are editable (click to rename).
    - Below the tab bar: renders the EconomyTab component with the active scenario's config.
    - For non-baseline tabs, wrap each parameter control with DiffMarker showing baseline vs current value.
    - "Run All Scenarios" button below the tab content. Disabled when only baseline exists or when `runningScenarios` is true. Shows spinner when running.
    - The ScenarioTabs component calls `scenarioStore.initFromSession(economyConfig, budgetAllocation)` on mount if tabs are empty.
