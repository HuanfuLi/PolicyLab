    **2. server/src/data/dataBootstrapPipeline.ts** — Create data-to-simulation converter (per D-07, D-09, D-10, D-11, D-12):

    ```typescript
    export function profileToEconomyConfig(profile: LocationProfile): {
      config: Partial<EconomyConfig>;
      budget: BudgetAllocation;
      confidence: Record<string, ConfidenceLevel>;
    }

    export interface AgentBlueprint {
      name: string;
      role: string;
      background: string;
      initialWealth: number;
      sector: 'agriculture' | 'industry' | 'services' | 'government';
    }

    export function generateAgentRoster(
      profile: LocationProfile,
      agentCount: number,
      baseFiat: number
    ): AgentBlueprint[]

    export function generateLawPromptContext(profile: LocationProfile): string
    ```

    **profileToEconomyConfig** mapping rules (per D-11):
    - `bankingEnabled: true`, `capitalMarketsEnabled: true`, `fiscalEnabled: true`, `inflationEnabled: true` — all auto-enabled per D-11.
    - `reserveRequirement`: clamp `realInterestRate / 100` to [0.03, 0.20], default 0.10 if missing.
    - `baseLoanInterestRate`: `annualRate / 100 / 12` (ITERATIONS_PER_YEAR = 12, per Pitfall 7). Default 0.005.
    - `depositInterestRate`: `baseLoanInterestRate * 0.4` (40% of lending rate).
    - BudgetAllocation: normalize military, health, education, infrastructure spending percentages to fractions summing to 1.0. Map: military->defense, health->welfare, education->education, remainder*0.3->infrastructure.
    - `budgetSpendingRate`: `govExpensePctGdp / 100` clamped to [0.05, 0.25], default 0.10.
    - Track confidence for each mapped parameter.

    **generateAgentRoster** (per D-09, D-10):
    - Calculate sector counts: `Math.round(agentCount * sectorPct)` for agriculture, industry, services. Assign remainder to services.
    - Call `distributeWealth(agentCount, baseFiat, gini / 100)` — NOTE: divide World Bank Gini by 100 per Pitfall 4.
    - Sort agents by sector, assign wealth values (wealthiest to industry/services, lowest to agriculture — reflects real patterns).
    - Roles: agriculture -> ["farmer", "ranch_hand", "agricultural_technician"], industry -> ["factory_worker", "engineer", "foreman"], services -> ["merchant", "teacher", "healthcare_worker", "clerk"]. Pick proportionally.
    - Background: placeholder string "Background to be generated by LLM" — the bootstrap route will fill via LLM call.

    **generateLawPromptContext** (per D-07 step 3):
    - Return a string containing location governance data formatted for LLM prompt injection. Include: country name, government type (from governance DataPoint), key regulations, property rights info.

    **1. server/src/routes/bootstrap.ts** — Create SSE bootstrap route (per D-07, D-08, D-12):

    Route: `POST /api/sessions/:id/bootstrap`

    Request body:
    ```typescript
    {
      location: string;           // Selected location display name
      countryCode: string;        // ISO 2-letter code from Photon
      coordinates: { lat: number; lon: number };
      scenario?: string;          // Policy scenario text (D-06)
      agentCount: number;         // 20-150 (D-09)
    }
    ```

    SSE pipeline (mirror design.ts pattern — same headers, same `res.write` format):

    Step 0: Validate session exists and is in 'idea-input' or 'brainstorming' stage.
    Step 1 (geocoding already done by frontend): Send `step_done` for geocoding.
    Step 2: `send({ type: 'step_start', step: 'demographics', stepIndex: 1, totalSteps: 6 })` then fetch demographics via locationDataService.
    Step 3: Economics indicators.
    Step 4: Governance (LLM call to generate governance summary from country name + any available data).
    Step 5: Infrastructure (LLM call similar to governance).
    Step 6: Generation — call `profileToEconomyConfig`, `generateAgentRoster`. If `scenario` text provided, call LLM to interpret as parameter deltas per D-12. Generate agent backgrounds via LLM (batch call with demographic context per D-09). Generate law document via LLM using `generateLawPromptContext`.

    After pipeline completes:
    - Update session stage to 'design-review'.
    - Store economyConfig and budgetAllocation in session.config JSON (partial merge via existing pattern).
    - Insert agents via agentRepo.
    - Store law document.
    - Store societyOverview (generated summary of the location).
    - Store locationProfile in session.config for diff markers (D-13, D-14).
    - Send `{ type: 'complete', sessionId: id }`.
    - End SSE stream.

    Error handling: Wrap each step in try/catch. On failure, send `step_fallback` event with the fallback source, continue with LLM estimation per D-02.

    Heartbeat: Send `{ type: 'heartbeat' }` every 10 seconds during long-running steps (per Pitfall 6).
