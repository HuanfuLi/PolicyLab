<objective>
Fix the bootstrap D-15 bug: when `economyConfig.fiscalEnabled === true` but no `fiscal_budgets` row exists for the session, runSimulation currently silently falls back to `DEFAULT_BUDGET_ALLOCATION`, masking real state loss. This plan (a) adds a startup assertion that throws descriptively, (b) removes the silent fallbacks at the two known sites, (c) closes the PUT /config flip path that can orphan the state, (d) ensures abort-reset either preserves the budget row or recreates it from session.config before simulation resumes.

Purpose: Close the invisible-bug class of "bootstrap appeared to succeed but fiscal state was silently default." Aligns with Phase 10's "bootstrap aborts with SSE error on LLM failure" philosophy — no silent fallbacks when user explicitly opted into fiscal.
Output: Startup assertion with root-cause guidance; two `?? DEFAULT_BUDGET_ALLOCATION` sites removed; PUT /config validation; abort-reset rehydration; passing fiscalBudgetAssertion test.
</objective>
