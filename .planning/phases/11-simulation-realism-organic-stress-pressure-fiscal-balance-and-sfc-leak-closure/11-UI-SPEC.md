## Scope Summary

Phase 11 is **backend-dominant**. Of 23 locked decisions, only 4 create new UI surface; all reuse the project's established token system and inline-style pattern. No new routes, no new pages, no new libraries.

## Spacing Scale

Declared values (project convention, multiples of 4; taken from existing components):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, badge inline padding |
| sm | 8px | Tight element spacing (between label and control) |

- SFC drift alert strip uses `8px 12px` compact padding (banner convention, not a full card).
- Governance toggle row uses `8px 0` vertical stack spacing (inline checkbox row, not a card).

## Interaction Contract

### Governance Toggle

- **Idle:** Unchecked box = governance off. Checked box = governance on (default).
- **Hover:** `opacity: 0.85`, cursor: pointer on the full label+checkbox row.
- **Focus:** 2px outline using `var(--primary-glow)` box-shadow (matches `input-glass:focus` convention).
- **Disabled (post-checkpoint):** opacity 0.5, cursor not-allowed. Tooltip: `Locked after simulation starts.`
- **Transition:** none (boolean state; no animation).

### TaxPolicyEditor (D-13 + GC4)

- **Idle:** Controlled form. User can switch kind (flat/progressive), edit rate inputs (0-50%, step 0.5), add/remove progressive brackets.
- **Hover/focus:** same pattern as other EconomyTab inputs — `var(--primary-glow)` box-shadow ring on focused inputs.
- **Disabled (post-checkpoint):** `opacity: 0.5`, `cursor: not-allowed`, `pointerEvents: none`. Title tooltip `"Locked after simulation starts."` on the container.
- **Validation errors:** Inline red text (`var(--color-red)`) below the bracket table when brackets violate invariants. Inputs remain enabled; server rejects on PUT if the client submits invalid data.
- **Source badge transition:** Badge switches from "Estimate" → "Custom" immediately on first change (source tracking: `sources.taxPolicy = 'user'`).
- **Bracket editor row:** Each row shows `upto` number input + `rate` number input + Remove button. Add bracket button appends a row with sensible default (`prev.upto + 1000`, rate 20%).

### SFC Drift Chart

- Inherits ALL interaction behavior from existing recharts panels in `EconomicDashboard.tsx`:
  - Hover crosshair shows all 7 line values + iteration number
  - Legend click toggles series visibility (recharts default)
  - ResponsiveContainer reflows on window resize
- Chart height: `220px` (10% taller than existing `200px` panels because 7 series need more vertical space to stay legible).

### Drift Alert Banner

- **Idle:** static banner, yellow (0.05 < |drift| ≤ 0.1) or red (|drift| > 0.1) background using `var(--panel-alpha-10)` tint of the semantic color.
- **Hover on "Jump to drift panel" link:** color shifts from `var(--text-main)` to `var(--primary)`.
- **Click on link:** `scrollIntoView({ behavior: 'smooth', block: 'start' })` on the `#sfc-drift-panel` element.
- **No dismiss button** per D-23.

## Accessibility Contract

- All checkboxes (new governance toggle) have `<label>` wrappers so clicking the label toggles the input.
- All icon-only indicators have `aria-label` (e.g., dot indicator: `aria-label="drift status: within threshold"`).
- SFC drift banner uses `role="alert"` and `aria-live="polite"` so screen readers announce new drift events without interrupting.
- Chart legend uses recharts defaults (already keyboard-navigable).
- Minimum color contrast: text-on-panel must pass WCAG AA — this is already enforced by the token system's dual-theme calibration (`--text-main` pairs with `--bg-color` in both themes). Do not introduce new foreground/background pairings.
- Toggle focus ring must be visible on both dark and light themes (use `box-shadow: 0 0 0 2px var(--primary-glow)`, same as `input-glass:focus`).

## Integration Contract (for Planner & Executor)

### Data shape assumptions

`TelemetryLog` (already in `shared/src/types.ts`) gains two optional fields per D-21. Planner must schedule this type extension before any UI task:

```typescript
interface TelemetryLog {
  // ... existing fields ...
  sfcDrift?: number;
  sfcDriftBySubsystem?: {
    banking: number;
    capmkt: number;
    fiscal: number;
    enforcement: number;
    trade: number;
    physicsActions: number;
  };
}
```

`EconomyConfig` (already in `shared/src/types.ts`) gains:

```typescript
interface EconomyConfig {
  // ... existing fields ...
  governanceEnabled?: boolean;  // default true
  taxPolicy?: {
    kind: 'flat' | 'progressive';
    rates: Record<string, number>;  // flat: { all: N } | progressive: { bracket0_1000: N, ... }
  };
}
```

Both fields are optional for backward compatibility (CLAUDE.md convention) so legacy sessions render the "empty state" copy specified above without code changes.

### Write path

Governance toggle updates flow through the existing `PUT /api/sessions/:id/config` endpoint (already used by other EconomyTab sliders). No new endpoint required.

TaxPolicy edits flow through `PUT /api/sessions/:id/config` with body `{ economyConfig: { taxPolicy, sources: { taxPolicy: 'user' } } }`. Server validates via `validateTaxPolicy` (coerce-comparison check); invalid shapes return 400. On manual edit, `sources.taxPolicy = 'user'` is persisted so future re-bootstraps can distinguish user preferences from stale derivations. (GC4 / forensics-G3 §5)

### Read path

`SfcDriftChart` reads from `simulationStore.macroHistory` (the existing accumulator populated by SSE telemetry polling, per the Phase 05-01 decision in STATE.md). No new store, no new SSE event type.

### Order of implementation (for planner reference)

1. Extend shared types (`TelemetryLog`, `EconomyConfig`) — unblocks UI and backend in parallel
2. Backend: emit `sfcDrift` + `sfcDriftBySubsystem` from `simulationRunner.ts`
3. Backend: persist `governanceEnabled` and `taxPolicy` via config endpoint
4. UI: `GovernanceToggle` + `TaxPolicyReadout` in `EconomyTab.tsx`
5. UI: `SfcDriftChart` + `SfcDriftBanner` in `EconomicDashboard.tsx`
6. UI: verify both dark and light themes render correctly (manual pass)
