**A. Module-level in-memory state (simulationRunner.ts):**

Add a module-level `Map<string, InflationState>` called `sessionInflationState` to store per-session inflation state between iterations. This avoids adding inflation data to the existing `sessionIterationMetrics` string (per Pitfall 5 from research).

**B. Inflation tick at end of iteration (simulationRunner.ts):**

After ALL action resolution, banking tick, and capital markets tick — but BEFORE the telemetry block and SFC audit — add the inflation tick:

1. Check `economyConfig.inflationEnabled` — skip if false/undefined (backward compat)
2. Read current market prices from `economyRepo.getPriceHistory()` or `marketPrices` for the current iteration. Build `currentPrices: Record<string, number>` with keys: food, tools, luxury_goods, raw_materials. Use VWAP where volume > 0, fall back to lastPrice, fall back to base price.
3. **Base price initialization:** If `economyConfig.cpiBasePrices` is null/empty AND this is iteration 1 (or first iteration with inflation enabled), set `cpiBasePrices` from current prices and persist to session config.
4. Get `m1Current` from the same source used for TelemetryLog.m1 (totalFiatSupply + loansOutstanding). Get `m1Previous` from the latest macro snapshot (macroSnapshotRepo.getLatestSnapshot).
5. Get `recentCpiHistory` from macroSnapshotRepo.getRecentSnapshots(sessionId, smoothingWindow).map(s => s.cpi).
6. Get `previousCpi` from the latest macro snapshot's cpi field (or null if no prior snapshot).
7. Call `computeInflation(input)` to get `InflationOutput`.
8. Insert macro snapshot via `macroSnapshotRepo.insertMacroSnapshot(db, { sessionId, iterationNumber, m0, m1: m1Current, cpi, inflationRate, inflationExpectations, totalLoansOutstanding, treasuryBalance })`.
9. Update `sessionInflationState.set(sessionId, { cpi, inflationRate, inflationExpectations })`.
10. Extend TelemetryLog with: `cpi`, `inflationRate`, `inflationExpectations` from the output.

**C. AMM feedback (simulationRunner.ts):**

After inserting the macro snapshot:

1. If `ammFeedbackFactor !== 1.0` AND `Math.abs(ammFeedbackFactor - 1) > 0.001`:
2. Get the primary AMM instance (food pool) from the session AMM registry
3. Call `amm.injectFiatReserve(amm.currentFiatReserve * (ammFeedbackFactor - 1))`
   - This increases fiat reserve, raising the spot price proportionally
   - k changes intentionally (nominal price level shift)
4. For each secondary AMM pool in multi-AMM registry (tools, luxury, raw_materials), apply the same scaling
5. Add trace: `"AMM feedback: scaled fiat reserves by factor ${ammFeedbackFactor}"`
6. **CRITICAL SFC note:** The AMM fiat reserve is already inside the SFC perimeter (counted by computeSystemFiatTotal). Injecting fiat INTO the AMM from nowhere would violate SFC. However, per the research and codebase analysis, `injectFiatReserve` is used by the UBI/demurrage cycle and the SFC audit already accounts for AMM reserve changes. Verify in the SFC test that `computeSystemFiatTotal` does not drift. If it DOES drift, switch to goods-reserve-only withdrawal approach: `amm.withdrawGoodsReserve(amm.currentGoodsReserve * (1 - 1/ammFeedbackFactor))` which raises prices by reducing goods supply instead.

**D. Central bank config updates (simulationRunner.ts):**

In the section where resolved actions are processed (after physics engine resolution, same area as ADJUST_TAX handling):

1. For each resolved SET_RESERVE_RATIO action: read the clamped value from the resolution result, update `economyConfig.reserveRequirement`, persist to session config
2. For each resolved SET_BASE_RATE action: read the clamped value, update `economyConfig.baseLoanInterestRate`, persist to session config
3. Follow the EXACT same pattern used by ADJUST_TAX for config persistence

**E. Cognitive injection — citizen agents (prompts.ts):**

1. Add an optional `inflationContext?: string` parameter to `buildNaturalIntentPrompt()` — append it after the existing optional parameters (citizenBankingContext, bankOperationsContext, citizenCapitalMarketContext)
2. When `inflationContext` is provided and non-empty, inject it into the prompt's economic context section (near where citizenBankingContext is injected)
3. Format: `"Economic conditions: CPI is ${cpi.toFixed(1)} (${inflationRate > 0 ? 'up' : 'down'} ${Math.abs(inflationRate).toFixed(1)}% from base). Inflation running at ${inflationRate.toFixed(1)}% this period. Consider adjusting wage demands or consumption strategy."`
4. Keep under 60 tokens

**F. Cognitive injection — central bank agent (prompts.ts):**

1. Define a `CentralBankContext` interface: `{ cpi: number; inflationRate: number; inflationExpectations: number; m1Current: number; m1GrowthRate: number; currentReserveRatio: number; currentBaseRate: number }`
2. Add an optional `centralBankContext?: CentralBankContext` parameter to `buildNaturalIntentPrompt()`
3. When provided, inject a block: `"CENTRAL BANK DASHBOARD: CPI ${cpi.toFixed(1)}, Inflation ${inflationRate.toFixed(1)}%/iter (trend: ${inflationExpectations.toFixed(1)}%), M1 growth ${(m1GrowthRate*100).toFixed(1)}%. Current policy: reserve ratio ${currentReserveRatio}, base rate ${currentBaseRate}. You may SET_RESERVE_RATIO (0.05-0.50) or SET_BASE_RATE (0.001-0.05)."`
4. Include the valid ranges in the prompt so the LLM knows the constraints (per Pitfall 4)

**G. Wire prompts in simulationRunner.ts:**

In the intent phase where `buildNaturalIntentPrompt` is called:
1. Read `sessionInflationState.get(sessionId)` for the PREVIOUS iteration's inflation data
2. Build the `inflationContext` string from the InflationState
3. If the agent role is `central_bank`, also build `centralBankContext` from the InflationState + current economyConfig values + m1GrowthRate from macro snapshot
4. Pass both to `buildNaturalIntentPrompt`

**H. Export/Import (importexport.ts):**

1. In the export function: read `macroSnapshotRepo.getSnapshotsBySession(sessionId)` and include in the export envelope as `macroSnapshots`
2. In the import function: if `data.macroSnapshots` exists, iterate and insert each via `macroSnapshotRepo.insertMacroSnapshot`
3. Follow the exact pattern used for depositAccounts/loanContracts export/import
